\begin{frame}{Problem}
  \begin{itemize}
    \item Containers share the host kernel; weak runtime confinement exposes kernel and host interfaces.
    \item Linux already has seccomp, AppArmor, and capabilities, but useful policies are hard to write and maintain.
    \item Sandboxed runtimes improve isolation but add overhead; cluster-side recorders require Kubernetes infrastructure.
  \end{itemize}
\end{frame}

\begin{frame}{Research Questions}
  \begin{block}{RQ1}
    Can the runtime generate useful seccomp, AppArmor, and capability profiles without extra infrastructure?
  \end{block}
  \begin{block}{RQ2}
    Does scan-then-enforce prevent command-injection exploitation and improve containment relative to stock \texttt{runc}?
  \end{block}
\end{frame}

\begin{frame}{Proposed Runtime Workflow}
  \begin{enumerate}
    \item Developer runs \texttt{runc run --security-scan} on representative traffic.
    \item The runtime relaxes confinement only in memory and records behaviour.
    \item It emits \texttt{seccomp.json}, \texttt{apparmor.profile}, and capability evidence.
    \item Finalisation narrows privileges from observed evidence.
    \item Later runs enforce the generated profiles as ordinary OCI inputs.
  \end{enumerate}
\end{frame}

\begin{frame}{Implementation Highlights}
  \begin{itemize}
    \item Syscalls: \texttt{oci-seccomp-bpf-hook} generates a deny-by-default allow-list.
    \item Capabilities: cgroup-wide \texttt{capable-bpfcc} tracing observes child processes.
    \item AppArmor: complain-mode profile is converted to enforce mode after audit collection.
    \item Hooks are hidden subcommands of the runtime binary; the OCI bundle receives data artifacts only.
  \end{itemize}
\end{frame}

\begin{frame}{Thesis Evaluation}
  \begin{itemize}
    \item Reproducible Flask laboratory with intentional command injection.
    \item Stock \texttt{runc}: reconnaissance, sensitive reads, reverse shell, mount probe, and persistence payloads succeed.
    \item Hardened scan-then-enforce: injected commands are blocked while legitimate ping and calendar upload remain functional.
    \item Controlled ablation shows defence in depth beyond the first denied \texttt{execve}.
  \end{itemize}
\end{frame}

\begin{frame}{After Thesis Submission: Additional Results}
  \begin{itemize}
    \item Performance campaign: 50 measured repetitions after warm-up on CPU, memory, network, and Redis workloads.
    \item Enforcement overhead: below 1\% on CPU, memory, and loopback network; about 5.5\% on Redis.
    \item Security corpus: 22 reproducers across stock \texttt{runc}, hardened raw, hardened enforced, and gVisor.
    \item Hardened enforced configuration blocks all 17 applicable attack reproducers and all 15 kernel-boundary probes.
  \end{itemize}
\end{frame}

\begin{frame}{Security Comparison}
  \begin{center}
  \begin{tabular}{lccc}
    \hline
    \textbf{Class} & \textbf{Stock runc} & \textbf{Enforced} & \textbf{gVisor} \\
    \hline
    Syscall & 5/5 & 5/5 & 5/5 \\
    Capability & 3/4 & 4/4 & 3/4 \\
    Filesystem & 0/3 & 3/3 & 1/3 \\
    Lateral & 1/3 & 3/3 & 1/3 \\
    Misconfig & 1/3 & n/a & 1/3 \\
    \hline
  \end{tabular}
  \end{center}
  \vspace{0.5em}
  \small{The misconfiguration row is an explicit limitation: profiles cannot repair \texttt{--privileged} or host namespace choices.}
\end{frame}

\begin{frame}{Conclusion and Remaining Work}
  \begin{itemize}
    \item Runtime-side profiling raises the security floor for plain OCI deployments.
    \item It keeps near-native performance for common workloads and avoids cluster-side recorder infrastructure.
    \item Remaining work: merge file capabilities, extend application coverage, export SPO-compatible resources, and repeat benchmarks on KVM/bare metal.
  \end{itemize}
\end{frame}
